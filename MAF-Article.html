Build an AdventureWorks AI Agent with Microsoft Agent Framework, ASP.NET Core 10, and Blazor WebAssembly

A useful business assistant must do more than generate a convincing paragraph. It must understand a request, ask for missing details, choose an allowed operation, and return trustworthy data. In this walkthrough, we build that assistant around AdventureWorks using a .NET 10 API, Azure OpenAI, Microsoft Agent Framework, and a Blazor WebAssembly chat interface.

The solution is named AdventureWorks_Agents. Its API project is AdventureWorksTool, and its browser application is AdventureWorksClient. The agent selects from 22 read-only database tools. The browser displays the agent's message and the actual SQL result rows separately.

What is Microsoft Agent Framework?

The official product name is Microsoft Agent Framework, abbreviated as MAF in this article. “Microsoft Agentic Framework” describes the idea, but is not the official name. It is an SDK for building agents and agent workflows. An agent combines model access, instructions, tools, and conversation context so it can decide how to respond or which application capability to invoke.

A basic chatbot generates text from messages. A tool-calling agent can also ask the application to execute a described function, receive its result, and continue the interaction. The language model proposes tool calls; application code executes them. The model does not directly connect to SQL Server.

Our agent is a constrained, single-agent application. It is not a multi-agent workflow, a background autonomous worker, a vector-search/RAG system, or a text-to-SQL generator. All SQL is predefined by the developer. MAF supports broader agent and workflow scenarios, but this example deliberately uses a small subset that is easy to understand.

Advantages of Microsoft Agent Framework

  • Agent abstraction: application code works with an agent rather than manually treating every exchange as an unrelated completion.
  • Tools from existing methods: ordinary .NET methods become capabilities the model can select. We reuse an existing query processor instead of asking the model to invent SQL.
  • Conversation-aware interaction: the agent can interpret “Northwest” as an answer to a region question when previous messages are supplied.
  • Composition with Microsoft.Extensions.AI: the IChatClient abstraction and its middleware let us configure function invocation independently of the Azure client connection.
  • Controlled execution: registered tools, application validation, cancellation, and iteration settings constrain the available work. These controls complement, rather than replace, authentication and database permissions.
  • Room to grow: additional tools, observability, streaming, or coordinated workflows can be introduced later. They are capabilities of the ecosystem, not features automatically enabled by the code below.

Implementation architecture

The companion MAF-Architecture.pptx contains an editable architecture slide and a follow-up conversation slide. Export the architecture slide as a PNG and insert it at the placeholder. The diagram shows an important split: full business rows are not sent back to the model in this implementation.

  1. The browser sends a prompt and previous successful user/assistant text messages to POST /api/agent.
  2. The API validates them and creates a request-specific ChatClientAgent with the available tools.
  3. The configured Azure OpenAI deployment either produces a clarification question or requests a tool call.
  4. The function-invocation middleware calls AdventureworksTool, which calls AdventureWorksQueryProcessor.
  5. EF executes parameterized SELECT statements. ResponseData contains a status message and named-column rows.
  6. The tool stores ResponseData in its request-scoped collection and returns only the status string to the model.
  7. The API sends the agent's final message plus the stored results to the browser. Blazor renders the real rows as tables.

Prerequisites and scope

  • Visual Studio with .NET 10 and ASP.NET/Blazor development support, or the .NET 10 SDK and a suitable editor.
  • SQL Server with an AdventureWorks database containing the Sales, Production, Purchasing, HumanResources, and Person schemas used below. This workspace calls its context AdventureWorks2025Context; a database name does not guarantee its sales date range.
  • An Azure OpenAI resource and a deployed model supporting chat completions and function calling. Use your actual deployment name, not a hard-coded model name from an unrelated example.
  • An account permitted to query the required tables. Use a read-only database identity for deployment.

Step 6: Add the result envelope

Create Responses/ResponseData.cs. A dictionary result avoids writing a separate DTO for each SELECT shape. The SQL column aliases become dictionary keys; native values remain numbers, strings, dates, and so on. The reader converts database DBNull values to null before JSON serialization.

AdventureWorksTool/Responses/ResponseData.cs

namespace AdventureWorksTool.Responses
{
    public class ResponseData
    {
        public string Message { get; set; } = string.Empty;

        public IReadOnlyList<Dictionary<string, object?>> Data { get; init; } = [];

        public int Count => Data.Count;
    }
}

Count is calculated from Data instead of being maintained separately. “Retrieved 38 record(s).” is an execution status, not the business data. Keeping these concepts separate prevents the model's prose from becoming the authoritative source of sales totals.

Shared parameter and SQL rules

  • Date ranges are inclusive calendar dates: SQL compares the lower bound directly and uses less than DATEADD(day, 1, @to) for the upper bound. The C# methods use Date parameters and discard time-of-day for these filters.
  • Dates must be compatible with SQL datetime data: from is on/after 1753-01-01; to is before 9999-12-31 so adding one day is safe; from cannot exceed to. A null date bound leaves that side unrestricted.
  • Special-offer asOf is an instant, not a date-only filter. It must be within 1753-01-01 through 9999-12-31 23:59:59.997 in the database's time convention.
  • Sales status values are 1 In process, 2 Approved, 3 Backordered, 4 Rejected, 5 Shipped, 6 Cancelled. Purchase status values are 1 Pending, 2 Approved, 3 Rejected, 4 Complete. The original four sales summaries have no status argument.
  • Integer IDs and topN use SqlDbType.Int; status uses TinyInt; department/location use SmallInt; flags use Bit; strings use sized NVarChar. Optional null values are bound as DBNull.Value, not interpolated into SQL.
  • Most optional lookup IDs are filters rather than existence checks. An unknown ID can produce zero rows. The required order IDs are checked for positivity before execution.

AdventureWorksTool/Queries/AdventureWorksQueryProcessor.cs

using AdventureWorksTool.Models;
using AdventureWorksTool.Responses;
using Microsoft.Data.SqlClient;
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Diagnostics;
using Microsoft.EntityFrameworkCore.Infrastructure;
using Microsoft.EntityFrameworkCore.Storage;
using System.Data;

namespace AdventureWorksTool.Queries
{
    public sealed class AdventureWorksQueryProcessor
    {
        private readonly AdventureWorks2025Context context;

        // Store the database context used to run the read-only queries.
        public AdventureWorksQueryProcessor(AdventureWorks2025Context context)
        {
            ArgumentNullException.ThrowIfNull(context);
            this.context = context;
        }

        // CONVERT(char(7), d, 126) yields 'yyyy-MM' and avoids FORMAT(), which is markedly
        // slower when it has to run per row in a GROUP BY.
        private const string SalesByMonthYearSql = """
            SELECT
                CONVERT(char(7), soh.OrderDate, 126) AS Period,
                SUM(sod.LineTotal) AS Sales
            FROM Sales.SalesOrderHeader soh
            JOIN Sales.SalesOrderDetail sod ON soh.SalesOrderID = sod.SalesOrderID
            WHERE (@from IS NULL OR soh.OrderDate >= @from)
              AND (@to IS NULL OR soh.OrderDate < DATEADD(day, 1, @to))
            GROUP BY CONVERT(char(7), soh.OrderDate, 126)
            ORDER BY Period ASC;
            """;

        private const string TopProductsBySalesSql = """
            SELECT TOP (@topN)
                p.Name AS Product,
                SUM(sod.LineTotal) AS Sales
            FROM Production.Product p
            JOIN Sales.SalesOrderDetail sod ON p.ProductID = sod.ProductID
            JOIN Sales.SalesOrderHeader soh ON soh.SalesOrderID = sod.SalesOrderID
            WHERE (@from IS NULL OR soh.OrderDate >= @from)
              AND (@to IS NULL OR soh.OrderDate < DATEADD(day, 1, @to))
            GROUP BY p.Name
            ORDER BY Sales DESC;
            """;

        private const string SalesByCategorySql = """
            SELECT
                pc.Name AS Category,
                SUM(sod.LineTotal) AS Sales
            FROM Production.ProductCategory pc
            JOIN Production.ProductSubcategory ps ON pc.ProductCategoryID = ps.ProductCategoryID
            JOIN Production.Product p ON p.ProductSubcategoryID = ps.ProductSubcategoryID
            JOIN Sales.SalesOrderDetail sod ON p.ProductID = sod.ProductID
            JOIN Sales.SalesOrderHeader soh ON soh.SalesOrderID = sod.SalesOrderID
            WHERE (@from IS NULL OR soh.OrderDate >= @from)
              AND (@to IS NULL OR soh.OrderDate < DATEADD(day, 1, @to))
            GROUP BY pc.Name
            ORDER BY Sales DESC;
            """;

        // @region matches a territory name ('Northwest'), a country code ('US') or a
        // territory group ('Europe'), so the model does not have to know which it was given.
        private const string RevenueByRegionSql = """
            SELECT
                st.Name AS Region,
                SUM(sod.LineTotal) AS Revenue
            FROM Sales.SalesOrderHeader soh
            JOIN Sales.SalesOrderDetail sod ON soh.SalesOrderID = sod.SalesOrderID
            JOIN Sales.SalesTerritory st ON st.TerritoryID = soh.TerritoryID
            WHERE (@from IS NULL OR soh.OrderDate >= @from)
              AND (@to IS NULL OR soh.OrderDate < DATEADD(day, 1, @to))
              AND (@region IS NULL
                   OR st.Name = @region
                   OR st.CountryRegionCode = @region
                   OR st.[Group] = @region)
            GROUP BY st.Name
            ORDER BY Revenue DESC;
            """;

        // Bind every referenced parameter; use DBNull.Value for optional filters.
        // @topN is a required positive int; callers must enforce a maximum result size.
        // @from and @to are optional SQL date values (inclusive); @to must be before 9999-12-31.
        // Other filters are optional unless marked required. @name is a literal substring.
        // Sales uses SubTotal (before tax/freight); summaries include all statuses unless filtered.

        // Parameters: @topN, @customerId, @territoryId, @name.
        private const string CustomersSql = """
            SELECT TOP (@topN)
                c.CustomerID,
                c.AccountNumber,
                COALESCE(s.Name, NULLIF(LTRIM(RTRIM(CONCAT(p.FirstName, N' ', p.LastName))), N''), c.AccountNumber) AS Customer,
                CASE WHEN c.StoreID IS NULL THEN N'Individual' ELSE N'Store' END AS CustomerType,
                c.TerritoryID,
                st.Name AS Territory
            FROM Sales.Customer c
            LEFT JOIN Person.Person p ON p.BusinessEntityID = c.PersonID
            LEFT JOIN Sales.Store s ON s.BusinessEntityID = c.StoreID
            LEFT JOIN Sales.SalesTerritory st ON st.TerritoryID = c.TerritoryID
            WHERE (@customerId IS NULL OR c.CustomerID = @customerId)
              AND (@territoryId IS NULL OR c.TerritoryID = @territoryId)
              AND (@name IS NULL OR CHARINDEX(@name, s.Name) > 0
                   OR CHARINDEX(@name, CONCAT(p.FirstName, N' ', p.LastName)) > 0)
            ORDER BY Customer ASC, c.CustomerID ASC;
            """;

        // Parameters: @topN, @from, @to, @status (sales order status).
        private const string TopCustomersBySalesSql = """
            SELECT TOP (@topN)
                c.CustomerID,
                COALESCE(s.Name, NULLIF(LTRIM(RTRIM(CONCAT(p.FirstName, N' ', p.LastName))), N''), c.AccountNumber) AS Customer,
                COUNT_BIG(*) AS OrderCount,
                SUM(soh.SubTotal) AS Sales,
                MAX(soh.OrderDate) AS LastOrderDate
            FROM Sales.Customer c
            JOIN Sales.SalesOrderHeader soh ON soh.CustomerID = c.CustomerID
            LEFT JOIN Person.Person p ON p.BusinessEntityID = c.PersonID
            LEFT JOIN Sales.Store s ON s.BusinessEntityID = c.StoreID
            WHERE (@from IS NULL OR soh.OrderDate >= @from)
              AND (@to IS NULL OR soh.OrderDate < DATEADD(day, 1, @to))
              AND (@status IS NULL OR soh.Status = @status)
            GROUP BY c.CustomerID, c.AccountNumber, s.Name, p.FirstName, p.LastName
            ORDER BY Sales DESC, c.CustomerID ASC;
            """;

        // Parameters: @topN, @customerId, @status, @from, @to.
        // Sales status: 1 In process, 2 Approved, 3 Backordered, 4 Rejected, 5 Shipped, 6 Cancelled.
        private const string SalesOrdersSql = """
            SELECT TOP (@topN)
                soh.SalesOrderID,
                soh.SalesOrderNumber,
                soh.CustomerID,
                soh.OrderDate,
                soh.DueDate,
                soh.ShipDate,
                soh.Status,
                sm.Name AS ShipMethod,
                soh.SubTotal,
                soh.TaxAmt,
                soh.Freight,
                soh.TotalDue
            FROM Sales.SalesOrderHeader soh

        // Check shared limits, execute parameterized SQL through EF, and return rows keyed by column name.
        private async Task<ResponseData> ExecuteQueryAsync(
            string sql, CancellationToken cancellationToken, params SqlParameter[] parameters)
        {
            cancellationToken.ThrowIfCancellationRequested();

            if (parameters.FirstOrDefault(p => p.ParameterName == "@topN")?.Value is int topN &&
                (topN < 1 || topN > 1000))
            {
                throw new ArgumentOutOfRangeException(nameof(topN), "The row limit must be between 1 and 1000.");
            }

            var from = parameters.FirstOrDefault(p => p.ParameterName == "@from")?.Value as DateTime?;
            var to = parameters.FirstOrDefault(p => p.ParameterName == "@to")?.Value as DateTime?;
            var minimum = System.Data.SqlTypes.SqlDateTime.MinValue.Value.Date;

            if (from.HasValue && from.Value < minimum)
            {
                throw new ArgumentOutOfRangeException(nameof(from), "The start date must be on or after 1753-01-01.");
            }

            if (to.HasValue && (to.Value < minimum || to.Value == DateTime.MaxValue.Date))
            {
                throw new ArgumentOutOfRangeException(nameof(to), "The end date must be on or after 1753-01-01 and before 9999-12-31.");
            }

            if (from.HasValue && to.HasValue && from.Value > to.Value)
            {
                throw new ArgumentException("The end date must be on or after the start date.", nameof(to));
            }

            using var criticalSection = context.GetService<IConcurrencyDetector>().EnterCriticalSection();

            return await context.Database.CreateExecutionStrategy().ExecuteAsync(async token =>
            {
                // EF binds the supplied parameters and manages the context connection and transaction.
                var command = context.GetService<IRawSqlCommandBuilder>().Build(sql, parameters, context.Model);
                var commandParameters = new RelationalCommandParameterObject(
                    context.GetService<IRelationalConnection>(), command.ParameterValues, null, context,
                    context.GetService<IRelationalCommandDiagnosticsLogger>(), CommandSource.FromSqlQuery);

                await using var result = await command.RelationalCommand.ExecuteReaderAsync(commandParameters, token);
                var reader = result.DbDataReader;
                var columns = Enumerable.Range(0, reader.FieldCount).Select(reader.GetName).ToArray();
                var data = new List<Dictionary<string, object?>>();

                while (await reader.ReadAsync(token))
                {
                    var row = new Dictionary<string, object?>(columns.Length, StringComparer.OrdinalIgnoreCase);
                    for (var index = 0; index < columns.Length; index++)
                    {
                        row.Add(columns[index], await reader.IsDBNullAsync(index, token) ? null : reader.GetValue(index));
                    }

                    data.Add(row);
                }

                return new ResponseData
                {
                    Data = data,
                    Message = data.Count == 0 ? "No data found." : $"Retrieved {data.Count} record(s)."
                };
            }, cancellationToken);
        }

    }

How ExecuteQueryAsync works

  1. It observes cancellation and validates shared topN/date limits before issuing a command.
  2. It enters EF's concurrency detector. A DbContext is not safe for parallel operations; the agent middleware also disables concurrent tool invocation.
  3. It uses the context's execution strategy. The actual retry behavior depends on provider configuration; merely calling CreateExecutionStrategy does not promise automatic retries.
  4. IRawSqlCommandBuilder builds a relational command using supplied SqlParameter objects and context metadata. RelationalCommandParameterObject connects the command to the EF-managed connection, transaction context, and diagnostics.
  5. ExecuteReaderAsync opens the reader. Each row becomes a case-insensitive Dictionary<string, object?> keyed by the SQL column names. IsDBNullAsync converts database nulls to C# null.
  6. The reader is disposed with await using. The returned ResponseData contains the rows and either “No data found.” or a retrieved-row count. Exceptions are not converted into fake success results.

This reader uses lower-level EF relational services to support arbitrary result shapes. It is intentionally centralized in one method. These APIs are more version-sensitive than LINQ queries, so re-check them when changing EF versions. SELECT statements are read-only by design; database permissions should enforce that boundary independently.

Step 8: Add AdventureworksTool and register every function

Create AgentTools/AdventureworksTool.cs. Preserve the class spelling AdventureworksTool used by the application. This class bridges model-selected functions and database query methods; it contains no SQL of its own.

  • Constructor: receives the scoped query processor and rejects null.
  • AsTools: registers all 22 method delegates using AIFunctionFactory.Create. The catalog above lists every wrapper and registered name.
  • Each public async wrapper: forwards its filters, defaults, and cancellation token to its matching Get...Async query method. RevenueByTerritoryAsync deliberately maps to GetRevenueByRegionAsync.

  • Results: exposes a read-only view of the captured per-request results. Repeated successful calls remain separate entries; a failed query does not reach CaptureResult.

Program.cs explained in detail

  1. Application startup: WebApplication.CreateBuilder loads configuration and creates the service collection. AddDbContext uses DefaultConnection. The context, query processor, and tools are scoped to one HTTP request; the tool result list therefore does not leak rows between users.
  2. Azure client factory: the singleton IChatClient factory reads endpoint, key, and deployment. It rejects a non-HTTPS/invalid URI and missing key/deployment. The factory runs when the service is resolved, not necessarily at application startup.
  3. Client adaptation: AzureOpenAIClient creates the deployment chat client; AsIChatClient adapts it to Microsoft.Extensions.AI. The builder installs function invocation with logging. Parallel execution is disabled, iteration count is bounded at eight, and detailed errors are not sent to the model.
  4. Error infrastructure: AddProblemDetails and UseExceptionHandler provide a consistent error-response path for unhandled failures. Tool-call failures can also be handled by the invocation middleware and reported through agent text; do not assume every tool error necessarily becomes HTTP 500.
  5. CORS: the named BlazorClient policy permits only configured origins, POST, and Content-Type. With no origins configured, cross-origin browser access is denied. RequireCors applies the policy to the agent endpoint; routing precedes CORS middleware. CORS is not authentication.
  6. OpenAPI and Swagger: AddOpenApi registers document generation. In Development, MapOpenApi exposes /openapi/v1.json and UseSwaggerUI displays it at /swagger. The UI uses a relative URL to that document. It is not enabled by this code in Production.
  7. Request validation: the prompt is trimmed, required, and limited to 8,000 characters. Optional history has at most 20 messages, only user/assistant roles, at most 8,000 characters per nonempty message, and at most 40,000 history characters. Invalid values return a 400 validation problem.
  8. Conversation reconstruction: prior text becomes ChatMessage instances with ChatRole.User or ChatRole.Assistant; the current prompt is appended once. There is no server-side conversation database or session ID. History is untrusted context, not authorization or proof that a query previously succeeded.
  9. Agent creation: a new ChatClientAgent receives the shared client, its name, and ChatOptions. UseProvidedChatClientAsIs preserves the middleware already installed. Tools come from the request-scoped AdventureworksTool instance, not a singleton buffer.
  10. Instructions: vague sales requests are clarified into a report type. Region reports ask for territory/country/group/all territories when missing. Date-filtered reports ask for dates or all available dates. The agent asks one question at a time, remembers answers for the current request, and must not invent required IDs. Complete requests can run immediately.
  11. Tool-call control: AllowMultipleToolCalls=false requests a single tool call in a model response. It still permits subsequent calls over sequential invocation iterations. The model chooses among tools; application parameter checks remain independent of prompt wording.
  12. Run and response: RunAsync receives the reconstructed messages and request cancellation token. An empty agent text response produces a 502 problem. Otherwise Results.Ok returns message and a results array directly projected from captured ResponseData objects, with tool, message, count, and data.
  13. Route metadata: WithName, WithSummary, and Produces calls document the route/status codes. Produces(200) alone does not provide a strongly typed success-body schema. The actual response shape is explained in this article and represented by the client contracts.

Clarification is model-driven: instructions encourage the expected dialogue but are not a deterministic approval workflow. Verify them against your deployment. For sensitive operations, implement explicit application-state checks rather than relying only on model instructions. Here the operations are predefined read-only queries.

using System.Net.Http.Json;
using System.Text.Json;
using AdventureWorksClient.Contracts;

namespace AdventureWorksClient.Services;

public sealed class AgentApiClient(HttpClient httpClient)
{
    // Send the prompt and previous messages to the API, read its reply, and report HTTP errors.
    public async Task<AgentResponse> AskAsync(string prompt, List<AgentHistoryMessage> history, CancellationToken cancellationToken)
    {
        using var response = await httpClient.PostAsJsonAsync("api/agent", new { prompt, history }, cancellationToken);
        if (!response.IsSuccessStatusCode)
        {
            var message = $"The API returned HTTP {(int)response.StatusCode}. Please try again.";
            if (response.Content.Headers.ContentType?.MediaType == "application/problem+json")
            {
                try
                {
                    var problem = await response.Content.ReadFromJsonAsync<ApiProblem>(cancellationToken);
                    if (response.StatusCode == System.Net.HttpStatusCode.BadRequest && problem?.Errors?.Count > 0)
                    {
                        message = string.Join(" ", problem.Errors.Values.SelectMany(errors => errors));
                    }
                    else if (!string.IsNullOrWhiteSpace(problem?.Title))
                    {
                        message = $"{message} {problem.Title}";
                    }
                }
                catch (JsonException)
                {
                    // Keep the HTTP status when the server returns a malformed problem response.
                }
            }

            throw new HttpRequestException(message, null, response.StatusCode);
        }

        return await response.Content.ReadFromJsonAsync<AgentResponse>(cancellationToken)
            ?? throw new JsonException("The API returned an empty response.");
    }

    private sealed class ApiProblem
    {
        public string? Title { get; init; }
        public Dictionary<string, string[]>? Errors { get; init; }
    }
}

@code {
    [Parameter, EditorRequired]
    public AgentQueryResult Result { get; set; } = new();

    private const int PageSize = 25;
    private AgentQueryResult? _previousResult;
    private string[] _columns = [];
    private int _page;
    private int PageCount => Math.Max(1, (Result.Data.Count + PageSize - 1) / PageSize);

    // Build the column headings and return to the first page when a new result arrives.
    protected override void OnParametersSet()
    {
        if (!ReferenceEquals(Result, _previousResult))
        {
            _columns = Result.Data.SelectMany(row => row.Keys).Distinct(StringComparer.Ordinal).ToArray();
            _page = 0;
            _previousResult = Result;
        }
    }

    // Move back one page without going before the first page.
    private void Previous() => _page = Math.Max(0, _page - 1);
    // Move forward one page without going past the last page.
    private void Next() => _page = Math.Min(PageCount - 1, _page + 1);

    // Convert a JSON cell value to display text while keeping nulls and numbers recognizable.
    private static string Format(JsonElement value) => value.ValueKind switch
    {
        JsonValueKind.Null or JsonValueKind.Undefined => "null",
        JsonValueKind.String => value.GetString() ?? string.Empty,
        _ => value.GetRawText()
    };

Step 15: Add the AgentChat component with follow-up conversation support

Create Components/AgentChat.razor. There are two lists for different purposes: _messages displays user/agent entries and attached result tables, while _history contains only successful user/assistant text pairs to send with the next request. This prevents large tables from being sent to the model.

  • SendAsync: rejects invalid input/history, prevents duplicate in-flight submissions, displays the user prompt, and calls the API. Only a completed response adds both sides of the exchange to _history. The returned rows stay attached to the display entry.
  • Cancellation and errors: a CancellationTokenSource lets the Cancel button interrupt the request. HTTP, timeout/cancellation, and JSON errors produce readable messages.   • Dispose: cancels pending work and prevents a late reply from updating a removed component.
  • History limits: the client checks the same count/character limits before sending. If the stored history exceeds a limit after a completed exchange, the next request asks the user to clear chat instead of silently forgetting earlier answers.

    private readonly List<ChatEntry> _messages = [];
    private readonly List<AgentHistoryMessage> _history = [];
    private string _prompt = string.Empty;
    private string? _error;
    private string? _status;
    private bool _busy;
    private bool _disposed;
    private CancellationTokenSource? _requestCancellation;

    // Validate the prompt, call the API, and add completed exchanges to the chat history.
    // Failed or canceled requests keep the prompt available for retry without adding it to history.
    private async Task SendAsync()
    {
        if (_busy || _disposed)
        {
            return;
        }

        var prompt = _prompt.Trim();
        if (prompt.Length is 0 or > 8000)
        {
            _error = "Enter a prompt between 1 and 8,000 characters.";
            return;
        }

        if (_history.Count > 20 || _history.Sum(message => message.Text.Length) > 40000 ||
            _history.Any(message => message.Text.Length > 8000))
        {
            _error = "This chat has reached its history limit. Select Clear chat to start a new conversation.";
            return;
        }

        _error = null;
        _busy = true;
        _status = "The agent is checking your request and any missing details…";
        _messages.Add(new ChatEntry(true, prompt, null));
        using var cancellation = new CancellationTokenSource();
        _requestCancellation = cancellation;

        try
        {
            var response = await AgentApi.AskAsync(prompt, _history, cancellation.Token);
            if (!_disposed)
            {
                _history.Add(new AgentHistoryMessage { Role = "user", Text = prompt });
                _history.Add(new AgentHistoryMessage { Role = "assistant", Text = response.Message });
                _messages.Add(new ChatEntry(false, response.Message, response.Results));
                _prompt = string.Empty;
                _status = "Agent reply received. Answer any clarification question below, or ask another question.";
            }
        }
        catch (OperationCanceledException)
        {
            if (!_disposed)
            {
                _status = cancellation.IsCancellationRequested
                    ? "Request canceled. Your prompt is available to edit or retry."
                    : "The request timed out. Your prompt is available to retry.";
            }
        }
        catch (HttpRequestException exception)
        {
            if (!_disposed)
            {
                _error = exception.StatusCode.HasValue
                    ? exception.Message
                    : "Cannot reach the API. Check that it is running, the HTTPS certificate is trusted, and the API URL and CORS origin are configured correctly.";
                _status = "Request failed. Your prompt is available to retry.";
            }
        }
        catch (JsonException)
        {
            if (!_disposed)
            {
                _error = "The API returned an invalid response. Expected an agent message and a results array.";
                _status = "Request failed.";
            }
        }
        finally
        {
            _requestCancellation = null;
            _busy = false;
        }
    }

    // Ask the current HTTP request to stop when the user clicks Cancel request.
    private void Cancel() => _requestCancellation?.Cancel();

    // Remove the displayed messages, remembered conversation, and current input.
    private void Clear()
    {
        _messages.Clear();
        _history.Clear();
        _prompt = string.Empty;
        _error = null;
        _status = null;
    }

    // Cancel pending work and prevent reply updates after this component is removed.
    public void Dispose()
    {
        _disposed = true;
        _requestCancellation?.Cancel();
    }

Step 18: Understand the boundaries before deployment

This is an agentic API because the model selects tools and asks clarifying questions rather than simply executing a hard-coded route chosen by the user. However, the model receives only query status strings. It cannot analyze unseen sales rows or use a returned product ID to plan another query unless that value is supplied in subsequent conversation. The user can read actual rows in the UI, but the agent's message must not claim to have analyzed data it never received.

Conversation support is bounded browser-supplied text, not durable memory. The API reconstructs each run and does not retain previous tool-result messages. Untrusted history cannot be used to authorize access. Keep API authentication, authorization, rate limits, least-privilege database access, logging hygiene, and model usage budgets as explicit deployment work. CORS only controls browser cross-origin access; it does not stop nonbrowser callers.

Do not expose detailed SQL exceptions or configuration secrets in the browser. Keep the singleton model client free of request-specific rows, preserve sequential DbContext use, and verify any production identity change independently. This article uses API-key configuration to match the supplied implementation; it does not silently switch providers, models, or authentication schemes.

Conclusion

Microsoft Agent Framework lets us place a natural-language interface over existing .NET capabilities without giving a model unrestricted database access. In this solution, AzureOpenAIClient supplies model connectivity, IChatClient supplies the chat abstraction and invocation pipeline, ChatClientAgent handles the interaction, and AIFunctionFactory exposes 22 described query methods as tools.

AdventureWorksQueryProcessor remains responsible for predefined parameterized SQL. AdventureworksTool keeps real query rows separate from status text. The ASP.NET Core API validates requests and returns both the agent message and authoritative data. Blazor provides the conversation experience, remembers clarification answers, and renders the actual result rows safely. Together these pieces demonstrate a practical, understandable starting point for a read-only business-data agent.
